# 娜娜完整剧本编译 Skill

## 一、职责与层级位置

本 Skill 负责把上游已经确认的内容真正写成“人可以读、演员可以演、下游可以拆”的完整剧本正文。

生产链顺序为：

1. 剧作大纲：确定故事、人物目标、因果、冲突和结局；
2. **完整剧本：本 Skill 的职责**，把大纲、原文材料和用户约束转化为连续的画面、逐字台词和可见动作；
3. Scene 导演：在完整剧本确认后，确定每场的状态变化、信息控制、空间关系、演员策略和整体导演基线；
4. Shot：再把剧本拆成独立观看任务；
5. Sequence / Prompt：只组接已经通过门禁的 Shot，并编译成视频执行文本。

本 Skill 不输出 Shot、Sequence、Beat、镜头编号、精确秒数、景别清单、运镜方案或最终视频 Prompt。
不得用大纲、场次摘要、关键台词摘录或导演说明冒充完整剧本。

## 二、开始前的模式门禁

本 Skill 不自行猜测原文权限，必须接收上游已经建立的 `scriptMode`：

- `original`：没有外部原作文本约束；可以自由创作，但仍服从用户当前锁定的角色、设定、台词、结局和格式；
- `adaptation`：尽量保留原文结构，原文台词启用 `source-verbatim` 锁；不删字、不改写、不换说话人、不调换顺序、不修辞、不改标点。

使用前确认 `scriptMode`（原创 `original` 或改编 `adaptation`）；如果未明确，先向用户确认。改编原文台词如存在错字、歧义、冲突、重复或无法确认的边界，先列出问题，不擅自修正。本 Skill 可独立使用，也可以接收同仓库 [`story-outline`](../story-outline/SKILL.md) 已确认的故事蓝图；不得用摘要代替完整剧本。

## 三、输入与继承优先级

优先读取以下输入：

- 当前用户明确确认的剧情、台词、角色和改编要求；
- 已确认的原剧本正文；
- 已存在且经过确认的 Scene Director Blueprint 的 purpose、stateChange、dramaticAction、information、blocking、performances、endState；它是可选的补充约束，不是本 Skill 的必需前置；
- 故事大纲中的人物动机、核心规则、冲突推进和结局。

信息冲突时，优先级为：**当前用户指令 > 当前已确认逐字台词 > 已确认剧本 > Scene 导演蓝图 > 故事大纲**。

如果导演层已经有台词，默认视为已确认台词，必须原样继承。改编模式的原文台词优先级最高；除非用户明确要求，不得删减、改写、换说话人、调整顺序或擅自改变标点。

如果上游只有剧情意图、没有完整对白，可以为缺失部分创作新台词，但必须让对白前后完整、逻辑成立，并且不能把新写台词伪装成用户已经确认的原文。新写内容仍需服从上游已确定的人物关系、信息权限和状态变化。

如果上游台词本身存在缺失、冲突或无法连成因果，不要用旁白或动作偷偷补过去；先标出缺口，或在用户允许改编时做最小修补。

## 三、编译顺序：先因果，再正文

写正文前，内部先完成以下检查，不把检查过程整段泄漏到剧本里：

1. 本场开场时人物各自想得到什么；
2. 哪个动作、信息或台词使局面发生变化；
3. 每次台词回应的是前一句的哪一部分；
4. 哪些导演层内容必须在正文中被看见，哪些仍然属于隐藏信息；
5. 场景结束时人物、道具、空间、关系和信息各自变成什么状态。

剧本正文必须让读者不看大纲也能理解：人物为什么在这里、为什么现在说这句话、为什么接着发生这个动作，以及动作之后局面如何改变。

## 四、固定正文格式

默认使用以下结构，不用额外的“Beat”“表演”“导演阐述”中间层：

```markdown
# 剧本名

## 第一场｜场名

【画面】
场景开始时，交代时间、地点、可见空间、主要光色或空气状态、人物初始位置、关键道具和当前关系。

【动作】
角色或物品发生可见交互；写清动作主体、方向、接触、受力和直接结果。

【台词】
角色A：“逐字台词。”

【动作】
紧邻台词写角色能被拍到的反应、停顿、视线、姿态变化或下一步物理行为。

【台词】
角色B：“逐字台词。”

【画面】
只有当人物位置、空间关系、道具状态、环境状态或可见信息发生实质变化时，更新画面。
```

正文规则：

- 每场开头必须有一次【画面】；
- 【画面】是当前可见状态，不写镜头、景别、焦段、运镜或模型执行指令；
- 同一个静态场景连续对白之间不重复贴同一段画面；
- 发生人物移动、物品碰撞、武器交锋、环境受力、空间阻断或状态结果时，才写【动作】；
- 对白前后的演员指导也放在紧邻的【动作】中，不能另列脱离台词的“表演：”段落；
- 【动作】只写可见行为，不把“她很紧张”“他很悲伤”“气氛紧张”当作动作；
- 【台词】只放实际说出的完整台词，不在动作里重复台词正文；
- 旁白、内心独白若确实属于剧本声音，可在【台词】下明确标注“旁白：”或“内心独白：”，不要混进画面和动作；
- 不能使用“上一镜头可知”“如前文所述”“人物保持原姿势”等依赖外部上下文的写法。

## 五、【画面】的写法

【画面】承担每个正文片段开头的可见场景交代，但不是导演蓝图的复制品。

首次出现时至少交代：

- 当前地点和时间状态；
- 读者能看到的空间结构和出口；
- 人物初始位置、朝向和相互距离；
- 会参与后续行动的道具或环境元素；
- 与剧情有关的光色、天气、雾、烟、雨、尘等可见状态。

后续更新只写变化后的结果，例如：

```text
【画面】
石桥侧绳已经断裂，桥身向溪谷倾斜。闻霜站在对岸，木匣仍抱在胸前；裴烬留在近岸，手里多了一枚铜印。
```

不要把以下内容写进【画面】：

- “电影感、高级、氛围感拉满”等无法执行的空词；
- 导演层的 purpose、戏剧功能、状态转折、任务说明或审核话术；
- “镜头推近、环绕、低机位、景别、焦点、景深”等 Shot / Camera 指令；
- 尚未允许观众知道的秘密或为了证明模型理解而安排的隐藏物露出。

## 六、【台词】的完整性与逻辑

完整剧本不是把几句台词排在一起，而是保留完整的说话过程：

1. 前一句提出请求、试探、判断、隐瞒或威胁；
2. 后一句必须真正回应、反击、转移、补充或改变它；
3. 台词之间允许沉默和动作，但不能跳过导致关系变化的关键回应；
4. 说完一句后，必须能看出它对下一步动作或关系造成了什么影响；
5. 每个角色的说话目的和语气策略要符合 Scene 导演层，不可让人物突然换人格。

每句台词前后都要有就地的、可拍的行为指导。例如：

```markdown
【动作】
裴烬没有拔剑，只用剑鞘压住闻霜的剑锋，抬眼确认她仍护着怀中的木匣。

【台词】
裴烬：“你若只是送一封信，不必走这条没有回头路的竹桥。”

【动作】
闻霜把木匣向身后收紧，脚尖仍朝着石桥出口，没有退让。

【台词】
闻霜：“我送的不是信，是你七年前没能活着看到的真相。”
```

禁止：

- 先连续堆完所有台词，再在末尾统一写一段“表演指导”；
- 用孤立的“角色名：”作为表演指令；
- 写“他说完后情绪复杂”“她表现出坚定”等没有可见行为的空泛说明；
- 为了让对白更像电影而改写已确认台词；
- 同一句台词既放在【台词】又完整复制到【动作】或【画面】中；
- 把不同角色的多轮问答压成一段没有前后关系的对白块。

单一角色的长台词可以完整保留，不因长度机械切碎。只有当原文已经有自然停顿、说话人变化、动作结果或关系主动权变化时，才在正文中自然分段；不得在普通词组中间改断台词。

## 七、【动作】的基本原则

【动作】不是动作清单，也不是情绪注释。每个动作至少回答：

- 谁在做；
- 对谁或什么做；
- 朝哪个方向、以什么方式发生；
- 接触或受力是否成功；
- 直接造成了什么可见结果；
- 这个结果如何改变下一步。

人物动作、物品动作和环境反应要保持状态连续：

```text
斩断绳索 → 木桥向一侧下沉 → 后续人物必须改变落脚位置；
剑锋划破衣袖 → 裂口在后续画面中继续存在；
火焰烧断帷幕 → 帷幕不应在下一段恢复完整。
```

心理只通过可见行为表达，而且只保留真正有叙事作用的行为：视线、身体朝向、手部力度、停顿、呼吸、重心、距离和话音落下后的反应。不要给每个情绪都配一串抿嘴、摸头发、调整坐姿等证明性动作。

## 八、武打、追车与特效动作设计

遇到动作戏，不能直接写“双方展开激烈打斗”“车辆高速追逐”“特效轰然爆发”。下笔前先设计完整的可见因果链，正文中再把它还原成连续的【动作】和必要的【画面】更新。

### 武打设计

至少明确：

1. 双方各自的目标，不只是“打赢”；
2. 空间轴、出口、障碍物和双方初始距离；
3. 首次威胁来自哪里；
4. 对方如何防守、躲避或改变位置；
5. 哪一次攻击命中、落空或被改变，接触造成什么重量和损伤；
6. 受力后的身体、武器、衣物和环境状态如何保持；
7. 哪次逆转改变胜负条件；
8. 高潮动作如何完成目标；
9. 结束时谁到达出口、谁被阻挡、谁带走了什么。

动作应当有节奏差：快速接近或交锋、短暂判断或停顿、突然改变方向、重击后的余波，再进入下一次行动。动作可以激烈，也可以有短暂的慢下来，但不能写成游戏连招、无重量的技能交换或随机特效展示。

禁止只写：

> 黑衣剑客使出绝招，两人激烈交锋，竹林被剑气摧毁。

应写成能够继续拆分的因果：

> 白衣剑客先刺向石桥出口，黑衣剑客横剑挡住；剑锋撞上桥栏，湿竹从受力点裂开。白衣剑客借反弹转身斩断悬桥绳索，桥面向溪谷倾斜，她抢先跃向对岸，黑衣剑客被迫留在近岸。

### 追逐 / 逃脱设计

明确谁追谁、追什么、终点在哪里、当前距离如何改变、障碍怎样造成追上或拉开距离，以及最终是否逃脱。每次躲避、撞击、转向或失速都要改变距离和路线，不能让人物在没有空间原因的情况下瞬移。

### 特效 / 奇观设计

特效必须有来源、触发动作、传播过程、对人物和环境的实际影响及结束状态：

- 火焰来自哪件物品，如何点燃，烧到什么，余烬留下什么；
- 法术由谁启动，能量沿什么路径传递，触碰后造成什么物理结果；
- 巨物如何进入空间，周围的尘、雨、水、建筑和人物如何响应；
- 特效结束后哪些光、碎片、伤痕、残骸或烟尘仍然存在。

不要用满屏泛光、无来源粒子、突然爆炸、贴图式能量或特效盖住人物来替代动作设计。下游需要镜头奇观时，剧本先提供真实的空间尺度、动作因果和环境后果，具体摄影路径留给 Shot 层。

## 九、导演层内容如何转成剧本

Scene 导演层中的内容必须被转化，而不是原样复制：

- `purpose` 转成角色正在争取的具体事情；
- `stateChange` 转成正文中可见的前后差异；
- `dramaticAction` 转成台词、动作和对方回应；
- `information` 转成角色知道、隐瞒或逐步发现的内容；
- `blocking` 转成有原因的人物移动和空间交互；
- `performances` 转成紧邻对白的可拍行为，不输出“表演”标签；
- `lighting / visualTone` 转成【画面】中的可见环境，不堆成独立质量词；
- `endState` 转成最后一次【画面】或【动作】中的具体结果。

导演层没有写出的动作，不能为了“让剧本丰富”随意添加；但若动作戏只有抽象概述，必须依照本 Skill 的武打 / 追逐 / 特效设计规则补足行动因果，否则不能交付为完整剧本。

## 十、场景边界与层级纪律

- 继承上游已确认的 canonical Scene 划分，不因为一句台词或一次普通走位擅自拆场；
- 明确时间跳跃、主要空间重建、世界层级切换或连续行动结束后才换场；
- 同一场景内可以有多次画面更新和动作结果，但不要制造 Beat、Shot Group 或其他中间层；
- 剧本正文不写 `Shot 1`、`Sequence 1`、`Beat`、景别、机位、运镜、精确秒数或 Prompt 区块；
- 不把导演蓝图的任务说明、审核意见、信息账本和资产需求泄漏进剧本正文；
- 不把“下个镜头”“镜头切到”“这里需要特写”等下游指令写进剧本。

## 十一、交付前硬性自检

交付前逐项检查：

### 剧本完整性

- 每一场都有开场【画面】；
- 正文包含连续的画面、台词和动作推进，而不是场次摘要；
- 不看大纲也能理解人物目标、冲突原因和结局变化；
- 每个重要导演层状态都有正文中的可见落点；
- 每个场景都有真正的结束状态。

### 台词完整性

- 已确认台词逐字保留；
- 台词顺序、说话人和标点未被擅自修改；
- 台词没有缺句、重复、错配或被动作重复；
- 每句台词前后都有紧邻且可拍的角色行为；
- 多轮对白存在真正的回应关系，没有把不同阶段压成一段；
- 长台词没有被机械删减或改写。

### 动作完整性

- 每个动作都有主体、对象、方向、接触 / 受力和结果；
- 武打不再是“激烈打斗”，而是完整的攻防、命中、反应、逆转和结局；
- 追逐有路线、距离、障碍和逃脱结果；
- 特效有来源、触发、传播、环境响应和持续状态；
- 不出现游戏 UI 感、无重量连招或无来源廉价光效；
- 物品和环境受损后在后文保持连续。

### 层级完整性

- 没有 Beat 中间层；
- 没有把导演说明冒充剧本；
- 没有 Shot / Sequence / Camera / Prompt 内容；
- 没有独立的“表演：”段落；
- 没有用“前文可知”逃避当前场景的主体、空间、动作或情绪交代。

## 十二、默认交付形态

默认只交付完整剧本正文和必要的极短交接备注。交接备注只能说明：台词是否全部继承、哪些台词为新写、哪些场景包含需要下游继续拆解的复杂动作；不得用备注替代正文。

当用户说“写完整剧本”“不是大纲”“逐字剧本”时，必须优先交付上述正文格式，不能退回到剧情梗概、导演蓝图或台词摘录。
