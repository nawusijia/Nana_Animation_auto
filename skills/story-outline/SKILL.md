# 娜娜剧本大纲引擎

## 何时使用

当用户要求以下任一任务时使用本 Skill：

- 从零创作一个故事大纲；
- 把已有小说、电影、游戏、人物设定、梗概或素材改编成新的剧本大纲；
- 对已有剧本大纲做诊断和优化。

本 Skill 的产物是 **Story Blueprint / 故事蓝图**。

**到故事大纲为止。** 不拆 Scene / Shot / Sequence，不写景别、机位、运镜、转场、声音设计或视频生成 Prompt。大纲确认后可以交给同仓库的 [`screenplay-writing`](../screenplay-writing/SKILL.md) 生成完整逐字剧本；后续 Scene 导演、资产提取和分镜由用户自己的工作流负责。

---

## 核心总原则

现代快节奏故事采用：

> **先用玩法抓人，再用人物留人。**

完整母骨架：

> **强钩子 → 极速原始状态 → 契机 → 进入颠倒世界 → 核心玩法连续兑现 → 玩法升级并反噬 → 谷底 → 人物弧光接管 → 最后一战验证改变 → 结局完成情绪 → 反向彩蛋留下余味。**

不要为了套结构而机械填表。结构的作用是保证故事持续产生观看欲、爽感、升级和人物重量。

---

# 一、先选工作模式

## Mode A｜原创剧本大纲

从零创作时，优先找到：

> **“这个故事最疯、最好玩、最值得观众继续看的核心玩法是什么？”**

不要先花大量篇幅做人物小传、世界观百科或主题阐释。

先证明：

- 只听核心玩法，观众就会想看；
- 玩法有清晰规则；
- 玩法可以连续玩不止一次；
- 每玩一轮都能产生新的选择、爽点、风险和升级。

玩法成立后，再让合适的人物进入其中，并让人物弧光在后半程接管故事。

## Mode B｜改编剧本大纲

改编时先拆原作，不要直接重写。

改编模式必须在开始前登记原文和模式状态。原文台词使用逐字锁：不删字、不改写、不换说话人、不调换顺序、不修辞、不改标点。大纲可以描述剧情功能和结构事实，但不得把台词改写成自己的概括后再当作原文交给下游；发现原文冲突或无法判断时，先停下标出问题。

先明确四类内容：

1. **必须保留**：原作最有辨识度、最有情感重量或用户明确锁定的核心；
2. **可以压缩**：对当前片长和媒介价值较低的铺垫、支线、重复信息；
3. **可以重构**：顺序、合并、节奏、入口方式；
4. **需要强化**：原作在快节奏视听媒介中不够强的钩子、玩法兑现、升级或人物落点。

再用本 Skill 的骨架重新组织，但“可以压缩 / 可以重构”只适用于用户允许的非台词结构处理，不能覆盖原文台词锁，也不能擅自改变用户明确锁定的场景顺序、人物关系、关键事件或结局方向。

**禁止为了套结构而改掉原作灵魂。** 用户明确保留的角色关系、设定、台词、结局或剧情节点必须原样保留，除非用户点名允许修改。改编任务应建立原文台词账本并贯穿后续写作；具体方法参见同仓库的 [`screenplay-writing`](../screenplay-writing/SKILL.md)。

## Mode C｜优化剧本大纲

优化时必须先诊断，再修改。

优先判断问题属于哪一层：

- 开头钩子不足；
- 核心玩法只是一次性噱头，不能持续；
- 玩法回合只是“更大、更难”，没有改变游戏条件；
- 文戏与武戏互不因果；
- 谷底只是倒霉或输掉一场，没有让旧生存方式失效；
- 人物动机没有在后半程重新获得重量；
- 最后一战只解决 Boss，没有验证人物改变；
- 结局情绪释放得太干净，没有余味。

只修诊断出的部分。

**未点名修改的已确认内容严格保留，不顺手润色，不偷偷重写。**

---

# 二、开头：六类强钩子至少命中两类

故事型视频开场原则上至少 **6 选 2**。组合自然即可，不为凑数堆满。

1. **结果冲击**：先给出严重结果——碎了、死了、受伤、坠落、毁坏、失踪等；
2. **异常现象**：世界规则反常——时间逆流、重力反转、物理规律失常等；
3. **视觉奇观**：巨大尺度、极端反差、罕见而夺目的视觉场面；
4. **进行中冲突**：追杀、打斗、枪击、争夺、逃亡、强对抗已经发生；
5. **信息矛盾**：身份、关系、事实彼此冲突，让观众认知无法闭合；
6. **迫近危机**：危险尚未完成，但正在逼近——倒计时、即将坠毁、即将暴露等。

开头的任务不是解释世界，而是制造一笔清晰的“叙事欠账”：

> **让观众产生“等一下，这是怎么回事？”**

---

# 三、原始状态：极速交代

主角原本是谁、处于什么生活状态，只交代到足以理解后续变化。

不要长时间铺陈人物履历。

这一阶段只需要建立：

> **主角原本处于状态 A。**

随后尽快出现契机，把主角拉入真正的故事。

---

# 四、契机：把主角拉进颠倒世界

契机负责完成：

> **原始状态 A → 核心玩法世界 B。**

最初动机可以很朴素：为了家人、工作、生计、钱、责任、生存、好奇、任务等。

**不要在故事刚开始时过度证明“为什么他绝对不能退出”。** 此刻观众更关心玩法是否值得看。只要因果足够让主角进入故事即可。

真正的动机重量应在观众已经进入故事之后，尤其在谷底附近重新显现。

---

# 五、核心玩法：必须是“有规则的颠倒世界”

核心玩法不是主题，不是单次猎奇事件，也不是漂亮设定。

合格的核心玩法至少具备：

- **颠倒世界**：主角进入与原本生活明显不同的新状态；
- **够疯、够有趣**：光听玩法就有观看欲；
- **明确规则**：观众能够理解这个世界“怎么玩”；
- **可持续运转**：不是一次事件，而是可以连续制造新局面；
- **高频回报**：持续提供爽感、惊奇、破局、反转、关系变化或危险升级。

常见爽感来源包括但不限于：

- 能力爽；
- 身份爽；
- 信息差爽；
- 利用规则钻空子的规则爽；
- 破局爽；
- 反转爽；
- 关系变化带来的爽感。

### 核心玩法一句话测试

去掉人物名字、主题阐释和背景百科后，只说玩法：

> **如果这句话本身还不能让人想继续看，玩法就还没有立住。**

---

# 六、玩法回合：根据片长使用 1～3+ 轮

核心玩法必须被连续兑现，而不是只展示一次。

片长越短，回合越少、越压缩；片长越长，可以增加回合或玩法变体。

每一轮基本结构：

> **进入本轮问题 → 主角采取行动 → 得到结果 → 结果暴露新的信息/代价 → 下一轮玩法条件改变。**

关键验收：

> **这一轮结束以后，局面必须和上一轮不一样。**

变化至少落在以下之一：

- 规则变了；
- 信息变了；
- 人物关系变了；
- 代价变了；
- 主角对世界的理解变了。

只增加敌人数量、爆炸规模、难度数字，不算真正的戏剧升级。

## 典型三轮节拍

### 第一轮｜玩法兑现 / 虚假胜利

目标：让观众真正体验“这个故事为什么好玩”。

第一次成功或失败都可以，但常见效果是：

> **主角和观众都产生“我好像搞懂怎么玩了”的感觉。**

虚假胜利尤其有效。

### 第二轮｜升级 / 暗藏危机

成功或失败都可以。

即使主角赢得更漂亮，结果里也要开始出现：

> **“事情可能不是你以为的那样。”**

玩法开始带毒，副作用、隐藏规则、关系裂痕、信息反转或更大代价逐渐浮现。

### 第三轮｜反噬 / 跌入谷底

不要让谷底只是突然倒霉。

最好让前两轮赖以成功的方法，在第三轮彻底反噬主角：

> **第一轮旧方法有效 → 第二轮旧方法开始付出代价 → 第三轮旧方法把主角送进谷底。**

---

# 七、文戏与武戏：彼此制造下一场

不要机械写成：

> 打一场 → 坐下来聊天 → 再打一场。

正确因果链：

> **行动/武戏改变事实 → 文戏消化事实并改变认知、关系或决定 → 新决定引发下一次行动。**

文戏不是休息段，而是在重新装填下一颗子弹。

---

# 八、谷底：人物开始接管故事

谷底不是“主角输得最惨”，而是：

> **主角原本赖以生存、获胜或保护自己的旧方法彻底失效。**

前半程观众主要追问：

> **“接下来会发生什么？”**

到了这里，应开始转成：

> **“这个人最后会怎么选？”**

此时重新激活最初动机。

开头的“为了女儿”“为了钱”“为了活下去”可能只是进入故事的许可证；到了谷底，它要升级成价值问题，例如：

> **“为了救女儿，你究竟愿意成为一个什么样的人？”**

---

# 九、人物弧光：必须能被“选择”看见

人物弧光不是让角色说“我成长了”。

最有效的表现是：

> **面对与故事开始时同类的价值冲突，他做出了不同的选择。**

设计时明确：

- **旧生存方式**：故事开始时，他靠什么原则、习惯或防御机制活着；
- **反噬过程**：这个方法如何先帮他赢，再开始伤害他；
- **谷底认知**：他终于意识到什么；
- **最终选择**：他最后做出什么和最初不同的决定。

人物弧光必须由剧情逼出来，不单独外挂一条“成长支线”。

---

# 十、最后一战：同时解决剧情问题与人物问题

Final Battle 不只是最大的动作场面、Boss 或爆炸。

它至少承担两件事：

1. **核心玩法的终极难题**；
2. **人物弧光的最终考试**。

理想状态：

> **主角必须用一个已经发生改变的自己，回答这个故事最难的一道题。**

结局可以赢，也可以输；人物弧光是否成立，不以物理胜负为唯一标准。

---

# 十一、结局：完成故事，但不要把情绪释放干净

使用 **“结局情绪对冲”**。

## 如果是悲剧 / 遗憾 / 意难平

给一点：

- 糖；
- 彩蛋；
- 余温；
- 另一种可能；
- 微小但真实的补偿。

让悲伤没有彻底封死，留下回味。

## 如果是大团圆 / 高满足结局

反过来给一点：

- 异常细节；
- 尚未结束的危机；
- 未解之谜；
- 某个不对劲的动作或信息。

让观众在“终于结束了”之后，多出一句：

> **“等等……”**

---

# 十二、输出格式

最终只输出故事大纲层，不提前导演化。

建议按以下结构交付：

## 1. 故事一句话
一句话说明人物 + 颠倒世界 + 核心玩法。

## 2. 开头钩子
明确本故事命中的至少两种钩子，以及它们如何同时发生。

## 3. 原始状态与契机
极速说明状态 A，以及什么把主角拉进状态 B。

## 4. 核心玩法
用一句话定义玩法，再列 2～5 条必要规则。

## 5. 玩法回合
逐轮写：

- 本轮问题；
- 主角行动；
- 结果；
- 爽点/观看回报；
- 暗藏代价；
- 下一轮改变了什么条件。

## 6. 谷底
明确哪一种旧生存方式在这里彻底失效。

## 7. 人物弧光
写清：旧选择 → 谷底认知 → 最终选择。

## 8. 最后一战
说明剧情终局问题，以及人物改变如何被真正验证。

## 9. 结局与余味
说明结局类型，以及使用什么“情绪对冲”。

---

# 十三、交付前自检门

Agent 在宣布大纲完成前，必须能够清楚回答：

1. 开头具体命中了哪两种以上钩子？
2. 核心玩法能否用一句话说清？
3. 去掉人物名字和主题后，这个玩法本身还好玩吗？
4. 为什么这个玩法能连续玩不止一次？
5. 每个玩法回合结束后，下一轮具体改变了什么条件？
6. 文戏有没有改变认知/关系/决定，并真正导致下一场行动？
7. 谷底摧毁了主角哪一种旧生存方式？
8. 最初动机在谷底之后为什么突然变得有重量？
9. 最后一战是否同时解决剧情问题和人物问题？
10. 人物弧光能否通过一个“与开头不同的最终选择”被看见？
11. 结局有没有留下与主情绪相反的一点余味？
12. 是否误入了 Scene / Shot / Sequence / 镜头 / 运镜 / 转场 / Prompt 层？如果有，删掉并退回大纲层。

只要有关键问题答不上来，就继续修大纲，不宣布完成。
